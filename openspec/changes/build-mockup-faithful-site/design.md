# Design

## Context

The static site now exists and follows the 1448 × 1086 flattened reference. Follow-up visual review now includes motion/depth refinements and a simpler hero/control treatment while preserving the accepted composition and confirmed server content. The user confirmed the URL and eight records; their confirmation is sufficient to publish them, but is not a claim of live status.

## Goals / Non-Goals

**Goals:** Refine the existing faithful, living scene with a seamless sun loop, an animated chrome wordmark and cursive neon subtitle, a low-view grid faded into the aligned city horizon, Steam-style pointer-tracked card depth, stronger whole-image character motion and obvious independent neon pulses; preserve selectable semantic text, copyable connection data and reduced-motion support.

**Non-Goals:** Accounts, signup, automated invitations, server administration, live status, a marketing landing page, pricing, extra navigation, or inventing a contact handle. Do not ship the mockup as the page or a single flattened background, copy complete CodePen compositions, or add a runtime dependency for visual effects.

## Decisions

### 1. Static source and content

Use a small static HTML/CSS/JS site with a minimal Node build only if needed for data templating. Emit essential text and all eight records as HTML so they remain readable without JavaScript. Store one canonical data file with management URL and ordered records (`game`, `hostname`, `variant`, `port`, `protocol`); render both text and copy targets from the same values. The default deploy artifact must include generated HTML, styles, scripts and assets, and work from root or a repository subpath using relative URLs. Restore a GitHub Pages Actions workflow appropriate for the chosen output. A server runtime or client-only rendering would unnecessarily undermine static hosting and no-script behavior.

Use the Portuguese wording in `docs/mockup-reference.md` for the title and panel content, with the follow-up hero subtitle `SERVERS PRIVADOS`. Omit the two-line hero intro per the follow-up request. The user later changed the footer label to `Crias 🄯 2026`; use the OpenMoji copyleft artwork and provide its CC BY-SA 4.0 attribution. Preserve the manual invite wording without fabricating Discord IDs, phone numbers, links or contact availability. Port and host values are in the persistent `private-server-access` spec. Any future changes to connection data belong in the canonical source, not multiple handwritten copies.

Check the reference image and detailed descriptions at each stage; do not use a random single anime mascot as a substitute. Record origin and any unresolved reuse rights in an asset manifest; avoid treating a source image's presence as proof of rights. If a usable recognizable asset cannot be created or obtained, mark its asset and verification tasks incomplete and report the blocker instead of substituting generic art or claiming visual fidelity.

### 3. Responsive scene

Use document flow for content and a separate decorative layer with per-element placement. At wide desktop use the reference collage arrangement, but stagger the left portraits across the upper area and alternate the lower four on a steady vertical rhythm (Kurisu near y=300, followed by Faye, Hinata and Rem). At widths above 1700 px, let only the left group move outward within the bounded collage; keep the right group and central content in place. At intermediate widths shrink margins and artwork before letting text compress. Around tablet size (up to 1099 px), reflow the character collage into a four-column in-flow gallery so it cannot disappear behind the panels; reflow the four steps and cards when their content needs room. On phones stack steps and cards in their original order; redistribute all fourteen separate character images across the hero and between/around sections. Allow extra page height and reserved decorative bands to keep all characters visible at 320 px without covering content; do not hide them or squeeze them into an illegible strip. Breakpoints are starting points, not fixed commitments; use actual available width and test long hostnames.

### 4. Motion and interaction

Treat the page as a layered scene: a low camera-angle perspective grid that fades into the city horizon; clearly visible, non-lockstep neon pulses; and independently tunable title, sky, sun, skyline, mountain and other decorative layers. Character illustrations remain static single images, but move noticeably as whole billboards with a gentle rotational sway and scale pulse, not frame-by-frame or articulated animation. CSS transforms/opacity are preferred for efficiency; keep effects near content quieter than the scene. Pointer light and surface tilt are approved refinements; Decision 6 defines their limits. They must not displace interactive hit areas.

Use CSS `prefers-reduced-motion` to stop CSS motion even without JS and stop the pointer-driven fluid solver when the preference is enabled. Do not show a manual pause/resume control. Apply preference changes immediately, and keep text and essential controls usable without scripts.

Render the URL and hostnames as selectable text. Progressively add nine accessible copy buttons; copy the URL in full and only the hostname for each server. Use Clipboard API where available, with a fallback or a clear error and selectable text. Announce brief success/failure in a live region, preserve focus, reserve feedback space and allow immediate repeats. Do not put ports into copied hostnames.

### 5. Verification and rollout

Visual review is mandatory, not a checkbox satisfied by automated DOM tests: render the page at 1448 × 1086 and compare side by side with `mockup.png`; check every character, statue, scene layer, logo, four-step panel, three game cards and footer against the reference. Capture mobile at 320, 375 and 430 px, tablet and wide desktop; scroll the full mobile page and count fourteen recognizable characters. Review reduced motion, no script, 200% zoom and keyboard focus; test nine copies including denied clipboard. Use testable browser checks for overflow, full values, copy payloads, and subpath paths, but do not treat them as a visual fidelity substitute. Record screenshots, browser used and actual limitations. Mark tasks incomplete if assets, review or environments are missing.

Build and verify locally before enabling the Pages workflow. Publish only when the user authorizes deployment; a committed workflow may deploy on a future push to the configured branch. To roll back, revert the implementation commit(s) and workflow in Git. No migration of old site content is needed.

### 6. Follow-up motion and pointer depth

Use the references as effect inspiration only: [vaporwave sun](https://codepen.io/stefanbomhof/pen/NWKBJzK), [retro text](https://codepen.io/K1LL3RFR4M3/pen/GRQXXjx), [smokey cursor](https://codepen.io/uiswarup/pen/QwjMRKN), and [Steam card hover](https://codepen.io/nelsonr/pen/WNQaZPb). Keep the existing site composition, content and independent scene layers.

Make the striped sun repeat seamlessly: the stripe animation must travel by exactly one repeat period per iteration, and the pulsing glow must meet at matching start/end values. Keep the glow restrained. Keep `CRIAS GAMES` as actual HTML text and preserve the current hero layout. Follow the supplied Retro Text Effect Pen's two-layer treatment: a dark blue base silhouette with glow and dark stroke, plus a transparent duplicate carrying the stepped blue/cyan/white/violet/magenta gradient and thin silver edge. Keep the horizontal bands inside the lettering; do not add a separate scan-line band behind it. Pulse the blue glow. Avoid the mostly-white fill and pink shadow treatment. Keep the subtitle in its existing cursive neon style with the updated text `SERVERS PRIVADOS`.

Define one shared scene horizon for the skyline baseline and the perspective grid origin. Set the sun behind the skyline at 75% of its current diameter and lift its visible lower edge about 260px above the baseline; open more sky above the city so the sun remains unobstructed by wireframe mountains confined to the side corners. Keep stars confined to the sky and faded out before the grid begins. Blend the city's bottom edge into the grid through a wide low fog band, not a hard horizontal seam. Harmonize the city with CSS opacity and color filters under normal alpha compositing; do not use screen blending on the city layer. Put the Japanese neon signage in front of the city layer. The grid begins at the same line behind the city, uses `perspective(280px) rotateX(80deg)` and fades from transparent near the skyline into the foreground grid. Preserve the mobile-specific scene positions while keeping this relationship coherent where the layers are shown.

Implement the pointer smoke as a GPU-accelerated WebGL2 stable-fluid simulation with velocity advection, pressure projection, vorticity confinement and dissipating pink/cyan dye, following the responsive shader-driven movement in the supplied cursor-smoke reference. Use 16-bit single/two-channel framebuffer formats for scalar and velocity fields, a 6-iteration pressure solve, a 64px short-side simulation grid and 384px short-side dye buffer. Cap the canvas at 0.6× CSS resolution and 500,000 pixels; bilinear browser scaling keeps this diffuse effect smooth while limiting fragment and memory bandwidth. Inject dye on the first pointer movement, preserve cursor deltas, and allow bounded variable time steps so the fluid does not lag behind on lower frame rates. Put its transparent, pointer-inert canvas above the hero collage and scenery, but below the title, Japanese signs, joining/server panels, their controls, and the footer. Use real DOM stacking for all text; do not clear rectangular text masks from the fluid canvas. Sleep the animation loop after the dye clears and disable it for reduced motion. Do not add external runtime dependencies. On desktop game cards, make mouse position directly control Steam-style perspective, surface brightness and a visible specular highlight. Raise each axis from the former two-degree cap to at least six degrees (at least three times the previous per-axis motion), add a small hover lift/scale, and reset smoothly on pointer leave. Keyboard focus must retain clear focus styling without tilt, and touch layouts must not emulate hover. Reduced motion disables fluid and card movement. Static content and hover/focus color feedback remain usable without JavaScript.

### 7. Streamlined hero and feedback

Remove the redundant two-line hero intro while preserving the title, neon subtitle, scenery, joining instructions and directory content. Place the sun at the skyline horizon behind the city; keep the building silhouette dominant with normal CSS opacity/filter compositing. Keep the low-view perspective grid aligned to the skyline baseline and softly faded at that edge.

Keep the live status region for copy feedback, but render its success/error message as a brief floating toast at the bottom of the viewport in a document-level stacking context above the footer. It must not occupy panel space, render underneath or become obscured by the copyleft label, shift the page, block pointer input, or obscure connection values; clear each message after a short display interval and allow an immediate repeated copy to announce again. Without JavaScript, the empty status region and copy-control behavior remain non-disruptive.

## Risks / Trade-offs

- [Recognizable separate artwork is difficult to obtain or recreate from a flattened mockup] → Work through the asset inventory explicitly, inspect each cutout and provenance, and report missing art rather than downgrade the target.
- [Fourteen illustrations make mobile tall or heavy] → Reserve responsive bands, use compressed appropriately sized assets and explicit dimensions, and review the full scroll rather than hiding characters.
- [Effects compromise legibility or performance] → Keep opaque content surfaces, limit simultaneous expensive blur, honor reduced motion and test on a phone-sized viewport.
- [Build or font assumptions break Pages] → Use relative paths, provide local/fallback fonts, test a repository subpath and no-script output.
